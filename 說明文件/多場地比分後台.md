# 多場地 LOG 後台

後台接收各場地傳來的 LOG，依前台「賽事名稱」分別存入同名 SQLite 資料庫。畫面選擇資料庫只會切換目前查看的 LOG 及 Excel API 輸出，不會影響其他賽事繼續同步。

## 使用方式

1. 後台電腦執行「開啟後台.bat」。視窗會顯示在螢幕中央。
2. 各場地在計分軟體的「系統設定 → 設定後台 IP」輸入後台 IP，只輸入 IP，不加 :5004。
3. 前台依賽事名稱在「場次log」內建立賽事子資料夾，完成 LOG 後每 5 秒自動同步。
4. 後台在「目前資料庫」選擇賽事資料庫，例如賽事名稱為「全國賽」，資料庫就是「全國賽.db」。
5. 依場地篩選或搜尋場次／選手。雙擊 LOG、按 Enter，或按「開啟選取場次 LOG」查看原網頁。
6. 「開啟資料庫位置」會開啟「後台資料庫」資料夾。

賽事名稱中的 Windows 非法檔名字元會被移除。相同賽事名稱會同步到同一個後台資料庫，不同賽事同時傳送也不會寫錯資料庫。舊版的 score_hub.db 仍可在下拉選單中查看；新版前台再次同步後會建立正確賽事名稱的資料庫。

## Excel API

後台畫面會顯示「Excel 表格」網址，也可以按「複製 Excel 表格網址」：

http://後台IP:5004/api/excel-data.csv

在 Excel 使用「資料 → 取得資料 → 從 Web」貼上這個網址，Power Query 會直接顯示成欄列資料表。第一列是欄位名稱；需要時可按「使用第一個資料列作為標題」。所有青方、紅方分數欄固定輸出小數點後三位。資料永遠取自後台目前選取的資料庫；切換資料庫後，在 Excel 按重新整理即可取得新資料。

程式整合若需要 JSON，仍可使用 http://後台IP:5004/api/excel-data 或 http://後台IP:5004/api/excel-data.json。
每筆資料有以下 30 欄，分數欄為數字，沒有成績時為 null：

- 組別：依序合併 Type / Category / Division / Phase。
- 場次：LOG 檔名的編號，例如 log_101.html 為 101。
- 籤號、青方姓名、青方單位、紅方姓名、紅方單位、名次。
- 青方總計_正確性、青方總計_表現性、青方總計_總分、青方原始總分。
- 青方R1_正確性、青方R1_表現性、青方R1_平均分。
- 青方R2_正確性、青方R2_表現性、青方R2_平均分。
- 紅方總計_正確性、紅方總計_表現性、紅方總計_總分、紅方原始總分。
- 紅方R1_正確性、紅方R1_表現性、紅方R1_平均分。
- 紅方R2_正確性、紅方R2_表現性、紅方R2_平均分。
- 狀態、結束時間。

一般賽的紅方欄位為 null。PK 賽會同時輸出青、紅雙方成績；名次沿用 LOG 的 BLUE、RED 或 DRAW。一般賽名次沿用 LOG 的數字。

## 同步與資料保存

場地只傳送所選賽事的完整 HTML LOG，不傳送前台比分資料庫。尚未寫完的 HTML 會等待下一輪，單次同步上限 32 MB。後台成功寫入資料庫後才回覆同步成功。

20 秒未收到更新會標示「未收到更新」，最後收到的 LOG 仍可查看。重新開啟後台會載入資料庫內容。每個場地以裝置識別碼區分，即使 IP 改變或場地編號相同，也不會互相覆蓋。

所有電腦須在同一區域網路，Wi-Fi 需允許裝置互連；後台防火牆需允許私人網路 TCP 5004。API 與同步服務只接受區域網路來源。

## 相關檔案

- 前台 settings.json 的 score_hub_ip：後台 IP，留空即停用同步。
- 前台 court_device_id.txt：自動產生的場地裝置識別碼。
- 前台 場次log/賽事名稱/：該賽事的 LOG 網頁。
- 後台資料庫/賽事名稱.db：場地、完整 LOG HTML 與同步時間。
- 後台資料庫/紀錄預覽/：開啟 LOG 時產生的安全網頁副本。
- score_hub_received.json：舊版資料來源，首次轉換後保留原檔。

場地端與後台都需更新並重啟。使用 EXE 時需重新打包。
