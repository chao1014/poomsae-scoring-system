# 品勢計分系統 - 打包與授權管理說明書 (管理端)

本說明書旨在指導品勢計分系統管理員/開發人員如何對品勢計分系統進行 **一鍵安全打包** 以及如何產生與管理 **設備授權金鑰**。

---

## 📂 打包與授權檔案結構

所有打包配置與授權的核心元件均統一收納於：  
👉 **[packaging_tools](file:///D:/品勢計分系統/packaging_tools/)** 資料夾

*   **`build_all.py`**：自動化打包腳本。基於穩定性考量已停用 PyArmor 加密，目前使用標準 PyInstaller 將系統以資料夾模式（onedir）打包，並內建數據保護備份機制。
*   **`license_generator.py`**：管理員專用 GUI，用來輸入機器碼並產生 `license.lic`。
*   **`license_verifier.py`**：內嵌於品勢計分主程式中的授權驗證函式庫。
*   **`register_gui.py`**：使用者端的授權錯誤提示與「一鍵匯入」註冊視窗。
*   **`updater.py`**：自動版本比對與覆寫更新的核心函式庫。

---

## 🛠️ 步驟一：如何進行一鍵打包

當您修改了品勢計分系統程式碼，需要產出最新版本的免安裝 `.exe` 檔給使用者：

1. 開啟終端機（如 PowerShell 或 cmd），進入本系統根目錄：
   ```bash
   cd D:\品勢計分系統
   ```
2. 執行打包指令：
   ```bash
   python packaging_tools/build_all.py
   ```
3. **打包成果**：
   打包完成後，發布目錄會輸出至 **`dist/PoomsaeScoringSystem/`** 資料夾：
   *   `dist/PoomsaeScoringSystem/PoomsaeScoringSystem.exe` (品勢計分主程式)
   *   `dist/PoomsaeScoringSystem/_internal/` (PyInstaller 編譯之相依檔案與執行庫資料夾)
   *   `dist/PoomsaeScoringSystem/ngrok_config.json` (雲端連線設定檔)
   *   `dist/PoomsaeScoringSystem/settings.json` (系統比賽參數設定檔)

> [!NOTE]
> *   **單一授權部署**：只需將產生的 `license.lic` 授權檔案直接放置於 `dist/PoomsaeScoringSystem/` 發布目錄下（與 `PoomsaeScoringSystem.exe` 同級），程式即會自動載入。
> *   **資料庫初始化**：程式在啟動時會自動偵測資料庫檔案，若不存在會自動建立。
> *   **重新打包數據保護機制**：為了解決重新打包清理舊目錄時，會導致已部署的授權與過磅歷史數據被誤刪的問題，打包腳本已整合自動備份與還原機制。重新打包時，`license.lic`、`.sys_time.dat`、`settings.json`、`ngrok_config.json` 以及所有歷史比賽資料庫（如 `tournament.db` 等 `.db` 檔案）將會**被自動備份並在打包後還原**，確保資料 100% 不會遺失。

## 🔑 步驟二：如何為新設備產生授權

本系統的授權綁定主機硬體（主機板 UUID 與 CPU ID）。每一台電腦在執行程式時，必須在 `dist/` 目錄下擁有專屬且簽章正確的 `license.lic` 檔案。

### 📌 取得本機機器碼的兩種方法

> [!TIP]
> **本機設備機器碼的標準格式**：  
> `TK-XXXX-XXXX-XXXX-XXXX` (共 16 碼十六進位，以 `TK-` 開頭，由 4 個破折號分隔之 4 碼區塊組成)。同一台電腦在主系統、過磅系統算出的機器碼皆會完全相同。

*   **方法一：使用者端雙擊程式自動獲取（最常用）**  
    請使用者在電腦上開啟 `PoomsaeScoringSystem.exe` 程式，畫面上將會彈出「設備授權註冊」視窗，請使用者點擊「**複製機器碼**」並將該碼傳送給您。
*   **方法二：開發者端終端機指令快速獲取**  
    在當前電腦的終端機（PowerShell 或 CMD）中執行以下指令，即可直接在螢幕上列印出本機機器碼：
    ```bash
    python packaging_tools/license_verifier.py
    ```

### 📝 產生授權憑證步驟

1. **啟動授權產生器**：
   在開發環境下執行：
   ```bash
   python packaging_tools/license_generator.py
   ```
2. **填寫授權資訊**：
   *   **授權對象**：輸入該設備名稱或體育館名稱（例如：`嘉義市立體育館`）。
   *   **設備機器碼**：貼上取得的 `TK-XXXX-XXXX-XXXX-XXXX` 機器碼。
   *   **到期日期**：格式為 `YYYY-MM-DD`（預設填寫為 `2026-12-31`）。
   *   **授權模組**：勾選 `品勢計分主系統 (poomsae)` 或 `萬用全功能授權 (*)`。
3. **生成檔案**：點擊「產生並儲存授權檔案」，將產出的 **`license.lic`** 檔案傳送給使用者，讓使用者放置於 `dist/` 目錄即可。

## 👁️ 使用者如何檢視授權期限？

1.  **檔案中檢視**：使用者可以直接以文字編輯器打開 `dist/license.lic`，裡面的 `"expire_date"` 欄位即代表其到期日期。

## ⚡ 自動更新機制 (Auto-Updater)

本系統支援「免版本號管理」的一鍵自動更新機制。品勢計分程式啟動時會自動對比伺服器與本地檔案特徵，以在無感狀態下維持最新版。

### 📡 1. 部署更新檔 (管理端)
當您有新編譯好的品勢計分軟體釋出時：
1. **直接複製**：將最新編譯的 `PoomsaeScoringSystem.exe` 檔案複製覆蓋丟入共用更新目錄：
   👉 **`Y:\競賽軟體\`** 即可，不需要做其他任何操作。

### ⚙️ 2. 設定更新來源 (用戶端)
*   **更新設定**：在 `dist/settings.json` 的 `"update_source"` 欄位設定。
*   **啟用更新**：設定 `"update_source": "Y:\\競賽軟體"` (預設已設定為此值)。
*   **關閉更新**：將 `"update_source"` 欄位留空即可。

> [!NOTE]
> 品勢計分系統與過磅系統共用同一個 `Y:\競賽軟體` 更新目錄，但因執行檔名稱不同（`PoomsaeScoringSystem.exe` vs `WeighIn.exe`），兩者互不干擾，可同時放置。

### 🔄 3. 更新比對與防鎖定覆寫流程
1. **特徵比對**：程式啟動時，會自動比對本地 `PoomsaeScoringSystem.exe` 與 `Y:\競賽軟體` 下執行檔的 **「檔案大小」** 與 **「修改時間」**。
2. **相同秒開**：特徵相同表示已是最新版，程式將在幾毫秒內秒開，不產生任何開機延遲。
3. **不同更新**：若特徵不同，程式會彈出更新提示。使用者同意後，程式會背景下載新版，自動調用 `temp_update/update_helper.bat` 並退出舊程式釋放鎖，隨後由批次檔完成檔案覆寫並重新開啟新版。

## 🔐 授權密鑰說明

> [!CAUTION]
> 品勢計分系統使用**獨立**的 HMAC 簽章密鑰（與跆拳道主系統分離）。
> 這意味著：
> *   品勢系統的 `license.lic` **不通用於**跆拳道主系統或過磅系統。
> *   必須使用品勢計分系統專屬的 `license_generator.py` 來產生授權。

## 🛡️ 離線防時光倒流（防竄改）機制

本系統具備離線狀態下的雙重防時間竄改防護，無須連接網際網路即可有效防止使用者將本機電腦時間往回調以繞過授權期限：

1. **簽發日期卡控 (`issue_date`)**：
   * 在使用 `license_generator.py` 產生授權時，系統會自動在 `license.lic` 中記錄當天的 `issue_date` 並將其納入 HMAC 簽章。
   * 程式啟動時，若本機時間早於簽發日期，將會被判定為時間異常而拒絕啟動。（向下相容：若為不含此欄位的舊授權，則預設以 `2026-01-01` 作為限制）。
2. **最後執行時間追蹤 (`.sys_time.dat`)**：
   * 授權驗證通過後，程式會在 `license.lic` 同目錄下自動產生一個加密且隱藏的時間紀錄檔 `.sys_time.dat`。
   * 每次正常啟動時，系統會驗證此檔案的簽章，並檢查本機目前時間是否早於該檔記錄的「最後執行時間」：
     * 若本機時間被調回過去，將會攔截並報錯 `TIME_TRAVEL_BACKWARD`。
     * 若手動用記事本修改該檔案以試圖推前時間，會因 HMAC 簽章不符而報錯 `TIME_RECORD_TAMPERED`。
     * 驗證通過後，系統會自動將該檔內容更新為目前最新本機時間。
